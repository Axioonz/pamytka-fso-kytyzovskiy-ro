# Личные кабинеты подразделений «Кутузовский»

Страницы подразделений работают через Supabase. Пароль общего профиля сайта (Yandex Cloud Function) не даёт права редактирования. Для изменений нужен отдельный аккаунт Supabase с записью в `public.kut_staff_access`.

## Первый администратор

1. На сайте войдите в нужный профиль и откройте «Подразделения» → «Личный кабинет» → «Создать аккаунт сотрудника».
2. Укажите собственную электронную почту и пароль. Если Supabase запрашивает подтверждение адреса, подтвердите письмо.
3. В Supabase Dashboard → SQL Editor выполните следующий запрос, **заменив адрес на email своей учётной записи**.

```sql
insert into public.kut_staff_access (user_id, full_name, role, department_code)
select id, 'Администратор', 'admin', null
from auth.users
where lower(email) = lower('ВАША_ПОЧТА@example.com')
on conflict (user_id) do update
  set role = 'admin', department_code = null;
```

Если письмо ещё не зарегистрировано в Auth, этот запрос не добавит пользователя. Проверьте наличие строки в `kut_staff_access` через SQL Editor.

После назначения администратор входит в свой кабинет и видит заявки сотрудников. Руководство утверждает их, выдавая роль редактора конкретного отдела. Сотрудники с ролью редактора не могут менять сведения других подразделений. Роль `viewer` разрешает только чтение.

## Содержимое

- `kut_departments`: собственное описание каждого подразделения.
- `kut_uniforms`: несколько комплектов формы, описание и путь к изображению.
- `kut_members`: состав подразделения, звание и должность.
- `kut_sections`: собственные инструкции и материалы подразделения.
- `kut_staff_access`: права кабинетов.
- `kut_access_requests`: заявки на доступ.
- `kut-uniforms` в Storage: фотографии комплектов, JPG/PNG/WebP до 5 МБ.

Прямое редактирование запрещается Postgres RLS, а не только JavaScript-кнопками. Секретные серверные ключи в исходниках сайта отсутствуют. Данные разделов этого сайта хранятся в отдельных таблицах `kut_*` и не изменяют записи действующего портала РМРП.

## Проверка

После публикации GitHub Pages открыть сайт под профилем отдела, проверить все пять вкладок и войти под учётной записью с правом редактора. Добавить тестовую форму с фотографией, запись сотрудника и материал. Проверить, что другой редактор не может изменять эти записи, а анонимный пользователь не может записывать данные в API.
