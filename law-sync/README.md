# Бесплатная локальная проверка законов

Требуются Python 3.10+ и зависимость: `py -3 -m pip install -r law-sync/requirements.txt`. Команды запускайте из папки памятки.

Первая авторизация: `py -3 law-sync/check.py --login`. Используется HTTP-клиент и сессия форума; пароль вводится скрыто, не сохраняется. Если форум требует CAPTCHA, второй фактор или браузерный вход, установите `py -3 -m pip install playwright`, затем `py -3 -m playwright install chromium` и выполните `py -3 law-sync/check.py --login --browser`. Войдите самостоятельно и нажмите Enter в консоли после открытия закона. Отдельный постоянный профиль хранится только локально.

Проверить один закон: `py -3 law-sync/check.py --id fso`. Все включённые законы: `py -3 law-sync/check.py`. Сначала используются HTTP-запросы с локальной сессией. Резервный Playwright включается только при блокировке HTTP 403/503 и наличии браузерного профиля. При окончании сессии автоматическая проверка прекращается с кодом 2; выполните вход снова.

Источники добавляются в `config.json`: уникальный `id`, `title`, официальный HTTPS `url`, `enabled: true`, `postIndex: 0`. Для нестандартной разметки можно указать `xpath` сообщения и `expectedText` — регулярное выражение для проверки текста. Устав выключен до получения источника.

База: `data/laws.json`; в каждой записи источник, дата редакции (если явно показана), последняя успешная проверка, хеш и статьи с главами. Пустая дата редакции означает, что её не удалось определить; дата подписи не выдается за дату редакции.

Перед записью создаётся `backups/<дата>/` с прежними базой и памяткой. Каждый файл заменяется атомарно. При ошибке записи памятки восстанавливаются обе прежние версии. Ошибочно полученный документ не меняется; успешно проверенные другие документы могут обновиться. Отчёты — `reports/latest.txt` и `latest.json`.

Обнаруживаются изменение/добавление/удаление статьи, явная отметка утраты силы, перенос одинакового текста на другой номер и изменение вне статей. Пробелы, переносы и HTML-разметка игнорируются. Перенумерация изменённого одновременно текста может отображаться как удаление и добавление — требует ручной оценки.

Ситуации и основания автоматически не переписываются. В отчёте и памятке помечаются связанные элементы. Отметки сохраняются между проверками; после ручной сверки уберите соответствующие ID из `pending` в базе. После изменения только этого списка запустите проверку успешно доступного документа, чтобы обновить отметки в HTML.

Windows: `powershell -File law-sync/schedule.ps1 -When Daily` создаёт ежедневное задание в 19:00, `-When Logon` — при входе. Используется текущий пользователь, постоянно работающий сервер не нужен. Перед этим проверьте, что команда `python` запускает установленный Python с зависимостями. Планировщик не создавался автоматически.

`.session/` содержит секретную сессию, исключена из Git и архива. Не помещайте её в папку публичного сайта и не отправляйте другим людям. `config.json`, база и `index.html` не содержат паролей или cookie. Само расположение файла сессии не заменяет ограничения доступа к вашей учётной записи Windows.

Живой вход с учётной записью пользователя требует его первого запуска. В среде подготовки HTTP-доступ к форуму заблокирован соединением; рабочий сценарий проверен локальными ответами, включая изменение закона, связь с памяткой, backup и отказ на странице входа.
